# overreacted

> Overreacted is Dan Abramov's personal blog of essays on React, React Server Components, JavaScript, UI engineering, the AT Protocol and the Lean proof language. It is for developers who want in-depth explanations of how these technologies work and the reasoning behind their design.

## Guides

- [One Roundtrip Per Navigation](https://overreacted.io/one-roundtrip-per-navigation/): An essay comparing data-fetching approaches for web navigations, from HTML apps through REST, loaders, GraphQL fragments, and React Server Components.
- [JSX Over The Wire](https://overreacted.io/jsx-over-the-wire/): Essay arguing for returning ViewModels or JSX from an API instead of REST resources, introducing Backend For Frontend and composable BFF patterns with code examples.
- [A Lean Syntax Primer](https://overreacted.io/a-lean-syntax-primer/): A syntax primer for the Lean programming language covering definitions, types, running code, proofs, namespaces and functions.

## Optional

- [Beyond Booleans](https://overreacted.io/beyond-booleans/): An essay explaining how Lean treats propositions as values and types, contrasting it with TypeScript's boolean type and showing how proofs work.
- [Progressive JSON](https://overreacted.io/progressive-json/): An essay arguing for progressive JSON streaming, explaining breadth-first chunking, outlining, and how React Server Components use Suspense.
- [What Does "use client" Do?](https://overreacted.io/what-does-use-client-do/): An essay explaining how the 'use client' and 'use server' directives in React Server Components work as typed module-level connections between server and client.
- [Impossible Components](https://overreacted.io/impossible-components/): A blog essay by Dan Abramov on composing self-contained React Server Components that combine backend data loading with frontend interactivity.
- [React as a UI Runtime](https://overreacted.io/react-as-a-ui-runtime/): A deep-dive essay explaining React's programming model as a UI runtime, covering host trees, elements, reconciliation, and components.
- [The Elements of UI Engineering](https://overreacted.io/the-elements-of-ui-engineering/): A 2018 essay listing recurring UI engineering problems such as consistency, latency, accessibility and resilience, with questions and tradeoffs for each.
- [Why Do React Hooks Rely on Call Order?](https://overreacted.io/why-do-hooks-rely-on-call-order/): A long essay explaining why React Hooks rely on call order, comparing alternative designs and their flaws such as name clashes and diamond problems.
- [Optimized for Change](https://overreacted.io/optimized-for-change/): An essay arguing that great APIs are designed to accommodate code changes over time, not just readability at first glance.
- [Preparing for a Tech Talk, Part 3: Content](https://overreacted.io/preparing-for-tech-talk-part-3-content/): Part three of a series by Dan Abramov on preparing tech talks, describing how he builds talk outlines, prototypes key sections, and rehearses slides.
- [The “Bug-O” Notation](https://overreacted.io/the-bug-o-notation/): An essay introducing the Bug-O notation, using DOM code examples to argue that API design affects how hard bugs are to find.
- [Things I Don’t Know as of 2018](https://overreacted.io/things-i-dont-know-as-of-2018/): Dan Abramov lists programming topics he admits not knowing well, and argues that admitting gaps doesn't devalue expertise.
- [I'm Doing a Little Consulting](https://overreacted.io/im-doing-a-little-consulting/): Dan Abramov announces he is offering hourly one-on-one consulting calls on React and React Native, and summarises his recent career and blog activity.
- [Why Does RSC Integrate with a Bundler?](https://overreacted.io/why-does-rsc-integrate-with-a-bundler/): Explains why React Server Components need bundler integration to serialize client modules, with examples of serialization, deserialization, and bundler bindings.
- [RSC for Astro Developers](https://overreacted.io/rsc-for-astro-developers/): An essay comparing Astro components and islands with React Server Components, explaining the server and client boundary and the tradeoffs of each model.
- [React for Two Computers](https://overreacted.io/react-for-two-computers/): An essay on distributed computation, comparing tags with function calls and exploring async, RPC and remote 'potential calls'; it is a post, not a structural page.
